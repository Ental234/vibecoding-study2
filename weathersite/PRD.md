# 날씨 사이트 PRD

## 1. 개요

### 배경 및 목적
전 세계 랜드마크를 지도에서 클릭하면 해당 지역의 실시간 날씨를 확인할 수 있는 사이트. 날씨와 시간대에 따라 배경이 함께 바뀌면서, 단순 정보 조회를 넘어 "그 장소의 지금"을 시각적으로 느낄 수 있게 하는 것이 핵심 경험.

Project Hub(개인 아카이빙 사이트)에 등록되는 신규 프로젝트로, Project Hub의 아카이브 톤에 맞춰 순수 HTML/CSS/JS로 구현한다.

### 타겟 사용자
- Ental 본인 (기술 학습 및 자기표현 목적의 사이드 프로젝트)
- Project Hub 방문자

---

## 2. 핵심 기능 요약

| 기능 | 설명 |
|---|---|
| 지도 & 랜드마크 마커 | 세계 지도 위 랜드마크 위치에 마커 표시, 클릭 시 날씨 조회 |
| 사이드패널 리스트 | 지도와 연동된 랜드마크 리스트 (지도 마커 클릭 ↔ 리스트 항목 선택 상호 연동) |
| 도시 검색 | Open-Meteo Geocoding API로 전 세계 아무 도시나 검색 가능 |
| 필터 | 지역(대륙/국가), 날씨 상태, 기온 범위 — 조합 적용(AND) 가능 |
| 배경 전환 | 선택된 위치의 날씨 + 시간대(낮/밤)에 따라 배경 테마 전환 |
| 로딩화면 | 날씨 데이터 요청 중 스피너 표시 |
| 에러화면 | API 실패, 검색 결과 없음 등 상황별 에러 메시지 |

## 3. 화면별 상세 기능

### 3.1 지도 & 랜드마크 마커
- 초기 화면에 세계 지도와 랜드마크 마커가 함께 표시됨
- 마커 클릭 시:
  1. 해당 좌표로 Open-Meteo Weather API 호출
  2. 사이드패널 리스트에서 해당 항목 자동 하이라이트
  3. 배경 테마를 날씨+시간대에 맞게 전환
- 선택된 마커는 시각적으로 구분(강조 스타일) 표시

### 3.2 사이드패널 리스트
- 지도 옆(또는 하단, 반응형에 따라)에 랜드마크 리스트 패널 배치
- 리스트 항목 클릭 → 지도 위 해당 마커로 자동 이동(pan/center) + 마커 클릭과 동일한 동작 수행
- 필터/검색 결과에 따라 리스트 항목이 실시간으로 갱신됨
- 리스트 각 항목에는 랜드마크명, 국가, 현재 온도/날씨 아이콘 간단 표시(선택 사항, v1 범위 내 가능하면 포함)

### 3.3 도시 검색창
- 사용자가 도시명을 입력하면 Open-Meteo Geocoding API로 검색
- 자동완성 형태로 검색 결과 목록 표시 (도시명, 국가 정도 표시)
- 검색 결과 선택 시:
  - 지도가 해당 좌표로 이동
  - 해당 위치의 날씨를 조회하여 마커처럼 취급 (단, 사전 정의된 "랜드마크"와는 별도로 "검색으로 추가된 위치"로 구분 표시 권장)
  - 배경 테마도 함께 전환
- 검색 결과가 없을 경우 → 에러 상태(3.5절 참고)로 안내

### 3.4 필터
- 필터 기준 (모두 동시 적용 가능, AND 조건):
  - **지역**: 대륙 또는 국가 단위 선택
  - **날씨 상태**: 맑음 / 흐림 / 비 / 눈 / 뇌우 등
  - **기온 범위**: 최소~최대 온도 슬라이더 또는 입력
- 필터 적용 결과는 지도 마커 표시 여부와 사이드패널 리스트에 동시 반영
- 필터로 인해 조건에 맞는 랜드마크가 없을 경우 → "조건에 맞는 결과가 없습니다" 안내 (에러화면과는 별도의 빈 상태 처리)

### 3.5 로딩화면
- 날씨 데이터 요청 중 로딩 스피너 표시
- 적용 시점:
  - 최초 페이지 진입 시 (초기 랜드마크 날씨 일괄 로딩, 있는 경우)
  - 마커/리스트 클릭 후 날씨 데이터 요청 중
  - 도시 검색 결과 선택 후 날씨 데이터 요청 중
- 로딩 중에는 이전 배경/데이터를 유지하거나 스피너를 오버레이 형태로 표시 (급격한 화면 전환 방지)

### 3.6 에러화면
| 상황 | 처리 |
|---|---|
| 날씨 API 요청 실패 (네트워크 오류, 서버 오류 등) | "날씨 정보를 불러오지 못했습니다" + 재시도 버튼 |
| Geocoding 검색 결과 없음 | "검색 결과가 없습니다. 도시명을 다시 확인해주세요" |
| 위치 좌표는 있으나 날씨 데이터가 비어있는 경우 | "해당 위치의 날씨 정보를 지원하지 않습니다" |
- 에러 상태에서도 지도/리스트 등 나머지 UI는 정상 동작 유지 (전체 화면을 덮는 에러가 아닌 해당 영역만 에러 처리)

## 4. 배경 전환 로직

### 기준
- **날씨 상태**: Open-Meteo weathercode를 대표 카테고리로 그룹화 (예: 맑음 / 흐림 / 비 / 눈 / 뇌우)
- **시간대**: Open-Meteo current_weather의 is_day 값을 사용해 낮/밤 2단계로 구분 (v1 범위)

### v1 배경 테마 매트릭스
5개 날씨 카테고리 × 2개 시간대(낮/밤) = 총 10종 배경 테마

> 아침/저녁 등 세분화된 시간대(4단계 이상)는 v1 범위 밖으로 별도 확인 필요 (7절 참고)

### 전환 방식
- 마커/리스트/검색으로 위치가 선택될 때마다 배경이 즉시(또는 짧은 트랜지션과 함께) 전환
- 배경 전환은 CSS 클래스 토글 또는 배경 이미지/그라디언트 교체 방식으로 구현 (애니메이션은 최소한으로, Project Hub 톤 유지)

## 5. 데이터 & API

### 5.1 Open-Meteo Weather API
- 용도: 선택된 좌표의 실시간 날씨(기온, 날씨코드, 낮/밤 여부) 조회
- 인증 불필요, 클라이언트에서 직접 호출 가능

### 5.2 Open-Meteo Geocoding API
- 용도: 도시 검색창의 자동완성 및 좌표 변환

### 5.3 초기 랜드마크 데이터셋
- 규모: 대륙별 대표 1~2개, 총 10~15개
- 데이터는 하드코딩된 JS 배열로 관리 (Project Hub 방식과 동일한 패턴)
- 각 항목 필드 예시: `{ name, country, continent, lat, lng }`
- 예시 후보 (확정은 별도 논의):
  - 아시아: 만리장성(중국), 앙코르와트(캄보디아)
  - 유럽: 에펠탑(프랑스), 콜로세움(이탈리아)
  - 북아메리카: 자유의 여신상(미국)
  - 남아메리카: 예수상(브라질)
  - 아프리카: 기자 피라미드(이집트)
  - 오세아니아: 시드니 오페라하우스(호주)

## 6. 기술 스택
- 순수 HTML/CSS/JS (프레임워크 없음, Project Hub 아카이브 방향과 일치)
- 지도 라이브러리: 별도 논의 필요 (예: Leaflet.js — 경량, CDN 사용 가능, 무료)
- 데이터: 랜드마크 목록은 JS 배열 하드코딩, 날씨/검색 데이터는 API 실시간 호출
- 백엔드 없음 (API는 클라이언트에서 직접 호출)

---

## 7. Out of Scope / 향후 고려사항
- 세분화된 시간대(아침/오후/저녁/밤 4단계 이상) 배경
- 사용자 커스텀 랜드마크 저장/즐겨찾기 (localStorage 활용 가능성은 있으나 v1 제외)
- 시간별/주간 날씨 예보 (v1은 현재 날씨만)
- 다국어 지원

---

## 8. 확인 필요 사항 (미결정)
- 지도 라이브러리 선택 (Leaflet.js 등 구체 후보 확정 필요)
- 랜드마크 데이터셋 최종 목록(10~15개) 확정
- 리스트 항목에 온도/날씨 아이콘 간단 표시 포함 여부 최종 확정
