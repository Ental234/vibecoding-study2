# PRD — 맛집 리뷰 서비스 (가칭 FoodReview)

> 최종 수정: 2026-08-14 · 버전: **v2.0**
> v1.0(개인 아카이브)에서 **일반 맛집 리뷰 서비스**로 기조를 전환했다. 변경 이유는 §11.

---

## 1. 개요

### 1.1 한 줄 정의
**다녀온 맛집에 리뷰를 남기고, 다른 사람의 리뷰로 다음에 갈 곳을 고르는 맛집 리뷰 서비스.**

### 1.2 해결하려는 문제
- 검색해서 나오는 리뷰 대부분이 **광고이거나 협찬**이라 믿기 어렵다
- 내가 다녀온 곳의 기록은 카톡·인스타·캡처 폴더에 흩어져 **다시 찾을 수 없다**
- 별점 평균만 봐서는 **내가 갈 만한 곳인지** 판단이 안 된다

### 1.3 목표
1. 식사 직후 **30초 안에** 리뷰를 남길 수 있다
2. 다른 사람의 **최근 리뷰**로 지금 갈 곳을 고를 수 있다
3. 내가 남긴 리뷰는 **태그·지역·별점으로 다시 찾을** 수 있다

### 1.4 비목표
- 수익화 — 광고·제휴·예약·배달 없음
- 소셜 그래프 — 팔로우·댓글·좋아요·DM 없음 (v2 검토)
- 실시간 채팅·알림
- 사장님 계정, 가게 답글

### 1.5 프로젝트 성격
**바이브 코딩 실습 프로젝트.** 사업적 성공이 아니라 *배포된 URL에서 실제로 동작하는 것*이 목표다.
이 문서는 사업 기획서가 아니라 **구현 착수용 실무 스펙**이다.

## 2. 타겟 사용자

### 2.1 페르소나: 로컬 탐방가

| 항목 | 내용 |
|---|---|
| 누구 | 주말마다 안 가본 동네를 걸어 다니며 가게를 발굴하는 사람 |
| 리뷰를 **읽을 때** | 광고 티 나는 블로그 말고, 실제로 다녀온 사람의 최근 한 줄이 필요하다 |
| 리뷰를 **쓸 때** | 길게 쓸 생각은 없다. 별점 + 한 줄 + 사진 한 장이면 충분하다 |
| 기기 | 대부분 **길 위에서 스마트폰**으로 접근 |

### 2.2 대표 시나리오

**S-1. 식사 직후 30초 리뷰**
계산을 기다리며 앱을 연다. 가게를 검색해 고르고, 별점을 누르고, 사진 한 장을 올린다. 끝.

**S-2. 처음 온 동네에서 고르기**
성수동에 왔다. 지도를 열면 근처 가게들의 별점이 보인다. 인기 탭에서 평점 높은 곳을 확인하고, 최근 리뷰 세 개를 읽고 결정한다.

**S-3. 3개월 전 그 집 다시 찾기**
"작년에 갔던 그 국밥집 어디였지?" → 내 기록에서 `#국밥` 태그 + 별점 4점 이상 필터 → 바로 나온다.

## 4. 기능 요구사항

> 각 기능은 **수용 기준(AC)** 을 모두 만족해야 완료로 판정한다.
> `F-10` 이상은 v2.0에서 신규 추가된 항목이다.

### F-01. 카카오 소셜 로그인

- [ ] AC-1: 로그인 화면에 "카카오로 시작하기" 버튼 하나만 존재한다
- [ ] AC-2: 최초 로그인 시 계정과 **프로필(닉네임)이 자동 생성**되고 피드로 진입한다
- [ ] AC-3: 리뷰 작성·수정·삭제는 로그인이 필요하다. 비로그인 사용자가 시도하면 로그인 화면으로 보낸다
- [ ] AC-4: **읽기는 로그인 없이 가능하다** — 랜딩·피드·인기·장소 상세·리뷰 상세
- [ ] AC-5: 브라우저를 껐다 켜도 세션이 유지된다
- [ ] AC-6: 설정에서 로그아웃할 수 있다

### F-02. 장소 검색
리뷰를 남길 가게를 카카오 로컬 API로 찾는다.

- [ ] AC-1: 검색어 입력 시 300ms 디바운스 후 결과가 표시된다
- [ ] AC-2: 결과 항목에 **가게명 / 카테고리 / 주소 / (가능하면) 현재 위치 기준 거리**가 보인다
- [ ] AC-3: 이미 리뷰가 있는 가게는 **평균 별점과 리뷰 수**가 함께 표시된다
- [ ] AC-4: 위치 권한을 허용하면 가까운 순으로 정렬된다. 거부해도 검색은 정상 동작한다
- [ ] AC-5: 결과를 선택하면 장소 정보(kakao place_id, 이름, 주소, 좌표, 카테고리)가 다음 화면으로 넘어간다
- [ ] AC-6: 검색 결과가 없으면 "찾는 가게가 없어요" 빈 상태를 보여준다

### F-03. 리뷰 CRUD
하나의 방문 = 하나의 리뷰. **작성 즉시 공개된다.**

- [ ] AC-1: 필수 입력은 **장소**와 **별점**뿐이다. 나머지는 모두 선택이다
- [ ] AC-2: 입력 항목 = 별점(1~5 정수), 방문일(기본값 오늘), 리뷰 내용(최대 500자), 재방문 의사(예/보통/아니오), 사진, 태그
- [ ] AC-3: 저장 시 즉시 피드·지도·장소 상세에 반영된다
- [ ] AC-4: 같은 가게에 여러 번 리뷰를 남길 수 있다 (방문 횟수만큼 쌓인다)
- [ ] AC-5: **본인 리뷰만** 수정·삭제할 수 있다. 삭제 시 확인 다이얼로그를 거친다
- [ ] AC-6: 삭제된 리뷰의 사진은 스토리지에서도 함께 제거된다
- [ ] AC-7: 작성 화면에 "작성한 리뷰는 모두에게 공개돼요" 안내 문구를 노출한다

### F-04. 사진

- [ ] AC-1: 리뷰당 최대 **5장**까지 업로드할 수 있다
- [ ] AC-2: 업로드 전 클라이언트에서 **긴 변 1600px, JPEG 품질 0.8**로 리사이즈한다
- [ ] AC-3: 업로드 중 진행 상태가 보이고, 실패 시 재시도할 수 있다
- [ ] AC-4: 첫 번째 사진이 피드·목록·지도 썸네일로 사용된다
- [ ] AC-5: 상세 화면에서 사진을 좌우로 넘겨볼 수 있다

### F-05. 지도

- [ ] AC-1: 진입 시 현재 위치(권한 거부 시 서울시청) 기준으로 지도가 열린다
- [ ] AC-2: **리뷰가 있는 모든 가게**가 핀으로 표시된다 (내 것만이 아니다)
- [ ] AC-3: 핀이 밀집하면 **클러스터링**되고, 확대하면 개별 핀으로 분리된다
- [ ] AC-4: 핀을 탭하면 하단에 가게명·평균 별점·리뷰 수·썸네일이 담긴 바텀시트가 뜬다
- [ ] AC-5: 바텀시트를 탭하면 **장소 상세**로 이동한다
- [ ] AC-6: 지도 우하단에 "현재 위치로" 버튼이 있다

### F-06. 내 기록

- [ ] AC-1: 내가 쓴 리뷰만 카드 형태로 보여준다 (썸네일·가게명·별점·방문일·태그)
- [ ] AC-2: 정렬 옵션 — **최신순(기본) / 별점순 / 가게명순**
- [ ] AC-3: 20개 단위 무한 스크롤로 로드한다
- [ ] AC-4: 리뷰가 하나도 없으면 "첫 리뷰를 남겨보세요" 빈 상태 + 추가 버튼을 보여준다

### F-07. 태그

- [ ] AC-1: 리뷰 작성 시 태그를 자유롭게 입력할 수 있다 (리뷰당 최대 10개)
- [ ] AC-2: 입력 중 **전체 사용자가 쓰는 인기 태그**가 자동완성으로 추천된다
- [ ] AC-3: 기본 추천 태그를 제공한다 — `혼밥` `데이트` `가성비` `재방문각` `분위기좋음` `웨이팅있음` `주차가능`
- [ ] AC-4: 태그는 **전역 공유**된다 (같은 이름은 같은 태그)

### F-08. 필터·검색

- [ ] AC-1: 키워드로 **가게명·리뷰 내용**을 검색할 수 있다
- [ ] AC-2: 필터 조건 — 태그(복수 선택, AND), 별점(N점 이상), 지역(시/구 단위), 방문 기간
- [ ] AC-3: 여러 조건을 **동시에** 적용할 수 있다
- [ ] AC-4: 적용된 필터가 칩으로 표시되고 개별 해제할 수 있다
- [ ] AC-5: 필터는 **피드·인기·내 기록** 각 화면에서 동일하게 동작한다

### F-09. 이미지 카드 내보내기

- [ ] AC-1: 리뷰 상세에서 "이미지로 저장"을 누르면 카드 이미지가 생성된다
- [ ] AC-2: 카드 구성 — 대표 사진, 가게명, 별점, 리뷰 한 줄, 방문일, 태그
- [ ] AC-3: 카드 비율은 **1:1(정사각)**
- [ ] AC-4: 생성된 이미지를 기기에 다운로드할 수 있다
- [ ] AC-5: **클라이언트에서만** 생성한다

### F-10. 랜딩 페이지 🆕
비로그인 사용자가 처음 만나는 `/`. **3초 안에 무슨 서비스인지 알게 한다.**

- [ ] AC-1: 다음 5개 섹션을 이 순서로 배치한다 — 히어로 / 인기 맛집 / 최근 리뷰 / 서비스 특징 / 푸터
- [ ] AC-2: **히어로** — 서비스 이름 + 한 줄 소개 + 가게 검색창 + `[시작하기]` 버튼
- [ ] AC-3: 히어로 검색창에 입력하면 `/search`로 이동한다 (로그인 불필요, 검색 결과는 누구나 볼 수 있다)
- [ ] AC-4: **인기 맛집** — 카드 3~6개. 데이터가 없으면 시드 데이터로 채운다 (§4 F-12 참조)
- [ ] AC-5: **최근 리뷰** — 별점 + 리뷰 한 줄이 가로로 흐르는 티커
- [ ] AC-6: **서비스 특징** — 준비 중 기능을 `Coming Soon` 뱃지와 함께 소개 (§4 F-15)
- [ ] AC-7: **푸터** — 만든 사람 / GitHub / 프로젝트 허브 링크 (아래 표의 값을 그대로 쓴다)
- [ ] AC-8: 로그인한 사용자가 `/`에 접근하면 `/feed`로 보낸다
- [ ] AC-9: 데스크톱과 모바일 모두에서 레이아웃이 깨지지 않는다 (랜딩만 넓은 화면을 쓴다)

**푸터 링크 확정값**

| 표기 | 값 | 비고 |
|---|---|---|
| 만든 사람 | **박승호** | 링크 없는 텍스트 |
| GitHub | `https://github.com/Ental234/FoodReview` | 새 탭 |
| 프로젝트 허브 | `file:///C:/Users/223/Desktop/Intro/index.html` | ⚠️ 아래 참조 |

> ⚠️ **프로젝트 허브는 `file://` 로컬 경로다.** 브라우저는 보안 정책상 `https://` 페이지에서 `file://`로의
> 이동을 차단하므로, **Vercel에 배포하면 이 링크는 클릭해도 아무 일도 일어나지 않는다.**
> 로컬 개발 서버(`localhost`)에서도 대부분의 브라우저가 막는다.
> 허브를 배포해 `https://` 주소가 생기면 그때 교체한다. 그전까지는 링크를 걸되
> **콘솔 에러가 나지 않도록 `<a>` 태그로만 두고 별도 처리는 하지 않는다.**

### F-11. 최근 리뷰 피드 🆕
로그인 후 홈 화면 `/feed`.

- [ ] AC-1: 모든 사용자의 리뷰를 **최신순**으로 보여준다
- [ ] AC-2: 카드에 작성자 닉네임·프로필 이미지·상대 시간("3시간 전")이 표시된다
- [ ] AC-3: 20개 단위 무한 스크롤
- [ ] AC-4: 카드를 탭하면 리뷰 상세로 이동한다
- [ ] AC-5: 비로그인 상태에서도 열람할 수 있다

### F-12. 인기 맛집 🆕
`/popular`. 랜딩의 "인기 맛집 카드"도 같은 데이터를 쓴다.

- [ ] AC-1: 집계 기준 = **리뷰 2개 이상**인 장소 중 평균 별점 내림차순, 동점 시 리뷰 수 내림차순
- [ ] AC-2: 카드에 대표 사진·가게명·평균 별점(소수 1자리)·리뷰 수·지역이 표시된다
- [ ] AC-3: 지역(시/구) 필터를 적용할 수 있다
- [ ] AC-4: 카드를 탭하면 장소 상세로 이동한다
- [ ] AC-5: 집계는 DB 뷰로 계산하며, 리뷰 작성·삭제 시 자동 반영된다

### F-13. 장소 상세 🆕
`/places/[id]`. 한 가게에 달린 모든 리뷰를 모아 보는 화면.

- [ ] AC-1: 상단에 가게명·주소·카테고리·평균 별점·리뷰 수·지도 미리보기
- [ ] AC-2: 별점 분포(5점 몇 개, 4점 몇 개…)를 막대로 보여준다
- [ ] AC-3: 그 가게의 모든 리뷰를 최신순으로 나열한다
- [ ] AC-4: `[리뷰 쓰기]` 버튼으로 이 가게의 리뷰 작성 화면에 바로 진입한다
- [ ] AC-5: 리뷰가 없는 가게면 "첫 리뷰를 남겨보세요" 빈 상태를 보여준다

### F-14. 프로필 🆕

- [ ] AC-1: 최초 로그인 시 카카오 닉네임·프로필 이미지를 가져와 `profiles`에 저장한다
- [ ] AC-2: 설정에서 닉네임을 변경할 수 있다 (2~12자)
- [ ] AC-3: 리뷰 카드의 작성자 이름을 탭하면 그 사람이 쓴 리뷰 목록을 볼 수 있다
- [ ] AC-4: 닉네임 중복은 허용한다 (식별자는 user_id)

### 5.7 `place_stats` 🆕 — VIEW

```sql
create view place_stats as
select
  p.id as place_id,
  count(r.id)                       as review_count,
  round(avg(r.rating)::numeric, 1)  as avg_rating
from places p
join reviews r on r.place_id = p.id
group by p.id;
```
인기 맛집(F-12)과 장소 상세(F-13)가 이 뷰를 읽는다.

### 5.8 RLS 정책 🔺 **v1.0에서 가장 크게 바뀐 부분**

v1.0은 `user_id = auth.uid()`로 모든 읽기를 차단했다. 공개 서비스가 되면서 **읽기를 전면 개방**한다.

| 테이블 | SELECT | INSERT / UPDATE / DELETE |
|---|---|---|
| `profiles` | 전체 허용 | 본인만 (`id = auth.uid()`) |
| `places` | 전체 허용 | authenticated |
| `reviews` | **전체 허용** | 본인만 (`user_id = auth.uid()`) |
| `review_photos` | **전체 허용** | 본인만 |
| `tags` / `review_tags` | 전체 허용 | authenticated |

### 5.9 Storage 🔺
버킷 `review-photos`를 **공개(public)** 로 전환한다. 남의 리뷰 사진도 보여야 하므로 signed URL이 필요 없다.
경로는 `{user_id}/{review_id}/{filename}` 유지 — 업로드 정책은 본인 폴더로 제한한다.

## 8. 시드 데이터

랜딩의 "인기 맛집"과 "최근 리뷰"는 **서비스 초기에 비어 있다.** 빈 랜딩은 죽은 서비스처럼 보이므로,
`supabase/seed.sql`로 **더미 계정 3~5개와 리뷰 20~30개**를 넣는다.

- 시드 계정 닉네임은 실제 사람으로 오인되지 않게 짓는다 (예: `맛집탐험대`, `주말산책러`)
- 시드 리뷰는 실존 가게의 **실제 평판을 흉내 내지 않는다.** 내용은 일반적인 문장으로 작성한다
- 시드 데이터임을 `profiles`에 `is_seed boolean default false`로 표시해 나중에 일괄 삭제할 수 있게 한다

## 12. 완료 기준

배포된 URL에서 **아래 흐름이 처음부터 끝까지 끊김 없이** 동작하면 완료다.

```
① 스마트폰으로 랜딩 접속 → 3초 안에 무슨 서비스인지 파악
② 로그인 없이 인기 맛집·최근 리뷰 열람
③ 카카오 로그인
④ 가게 검색 → 별점 + 사진 + 태그로 리뷰 작성
⑤ 피드 최상단에 내 리뷰가 올라온 것 확인
⑥ 지도에서 핀 확인 → 장소 상세에서 평균 별점 확인
⑦ 내 기록에서 태그로 필터링해 다시 찾기
⑧ 이미지 카드로 저장
```
