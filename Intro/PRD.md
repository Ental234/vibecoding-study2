# 프로젝트 허브 (Project Hub) PRD

## 1. 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 프로젝트 허브 (가칭) |
| 목적 | 나만의 실험/사이드프로젝트를 한곳에 모아두는 개인 아카이브 |
| 대상 사용자 | 제작자 본인 (셀프 아카이빙 용도) |
| 기술 스택 | HTML / CSS / JavaScript + GSAP 3.13 (CDN) |
| 데이터 관리 방식 | 코드 내 하드코딩 (정적 데이터, 별도 DB/CMS 없음) |
| 파일 구성 | `index.html`, `projects.html` 2개 (CSS/JS는 각 파일에 인라인) |

## 2. 배경 및 목적

여러 사이드 프로젝트가 흩어져 있는 상황을 정리하고, 하나의 인트로 페이지를 거쳐 프로젝트 목록으로 진입하는 개인 아카이브 허브를 만든다. 채용/외부 홍보보다는 본인의 실험 결과물을 모아 보고 회고하는 데 초점을 둔다.

## 3. 정보 구조 (IA)

```
1. 인트로 페이지 (index.html)
   └─ ENTER 버튼 클릭
2. 프로젝트 리스트 페이지 (projects.html)
   ├─ 프로젝트 카드 클릭 → 새 탭에서 실제 프로젝트로 이동
   └─ 좌측 상단 뒤로가기 → 인트로로 복귀
```

- 총 2개 화면(페이지)으로 구성되는 단순 구조
- 상세 페이지/모달은 없음 (카드 클릭 시 바로 외부 프로젝트로 이동)
- 두 화면을 **별도 HTML 파일**로 분리 (한 파일 안에서 섹션을 토글하는 방식이 아님)

## 4. 페이지별 요구사항

### 4.1 인트로 페이지

- 허브의 첫 진입 화면
- 화면 중앙에 라벨(`Archive`) / 타이틀 / 한 줄 설명 / **ENTER** 버튼을 세로로 배치
- ENTER 버튼 클릭 시 `projects.html`로 이동 (키보드 Enter 키로도 가능)
- 미니멀한 무드에 맞춰 여백을 넉넉히 활용, 타이틀/로고 텍스트 정도만 최소한으로 배치

**인터랙션**

| 요소 | 동작 |
|---|---|
| 타이틀 등장 | 글자 단위로 쪼개져 아래에서 순차적으로 올라옴 (GSAP SplitText, 28ms 간격) |
| ENTER 버튼 | 커서가 근처(바깥 110px)에 오면 버튼이 커서 쪽으로 끌려옴. 최대 이동 10px, 벗어나면 탄성 복귀 |
| 커서 잔상 | 테라코타 원 하나가 0.5초 지연으로 커서를 따라옴. 버튼 근처에서는 커지며 옅어짐 |
| 페이지 이탈 | ENTER 클릭 시 화면이 위로 살짝 밀리며 페이드아웃된 뒤 이동 |

### 4.2 프로젝트 리스트 페이지

- 상단에 뒤로가기 링크 + `Projects` 타이틀 + 프로젝트 개수 카운터
- 프로젝트를 **카드형**으로 그리드 배치
- 카드 구성 요소:
  - 썸네일 이미지 (16:9)
  - 프로젝트 제목
  - 짧은 설명(1~2줄)
  - 태그 칩 (선택)
- 카드 **전체가 링크**이며, 클릭 시 새 탭으로 실제 프로젝트 URL로 이동 (`target="_blank"` + `rel="noopener noreferrer"`)
- 열 수는 `auto-fill` + `minmax(260px, 1fr)`로 화면 폭에 따라 자동 조절 (4열 → 3열 → 2열 → 1열)

**인터랙션**

| 요소 | 동작 |
|---|---|
| 카드 등장 | 60ms 간격으로 순차적으로 페이드업 |
| 카드 hover | 배경이 살짝 밝아지고, 테두리·제목이 포인트 색으로 변함 |
| 3D 틸트 | 커서 위치에 따라 카드가 최대 7도 기울어짐. 커서 쪽 모서리가 앞으로 나옴 |
| 빛 반사 | 커서 위치를 따라 옅은 빛이 카드 표면을 스침 |
| 커서 잔상 | 인트로와 동일. 카드 위에서는 커지며 옅어짐 |

> ⚠️ **확대(scale)는 사용하지 않습니다.** 카드가 커지면 격자에서 튀어나와 주변 정렬이 흐트러지지만, 기울기는 카드가 차지하는 자리를 그대로 유지합니다. 자세한 수치는 `DESIGN.md` §6 참고.

## 5. 데이터 구조 (정적 하드코딩)

프로젝트 데이터는 JS 파일 내 배열/객체로 관리한다. 추후 확장을 고려해 아래와 같은 필드 구조를 권장한다.

```js
const projects = [
  {
    id: "project-01",
    title: "프로젝트 제목",
    description: "한두 줄 설명",
    thumbnail: "",              // 빈 문자열이면 대체 블록이 자동 표시됨
    url: "https://example.com",
    tags: ["React", "실험"],     // 선택 사항, 없으면 생략 가능
  },
  // ...
];
```

**썸네일 대체 처리**

아직 이미지가 준비되지 않은 상태에서도 레이아웃이 완성돼 보이도록 두 가지 경우를 모두 처리한다.

- `thumbnail`이 빈 문자열이면 → 팔레트 안의 그라데이션 블록 + 번호(`01`, `02`…)를 대신 표시
- 경로를 넣었으나 파일이 없으면 → 이미지 로드 실패를 감지해 같은 대체 블록으로 교체

이미지가 준비되면 `thumbnail`에 경로만 채우면 되고, 다른 코드는 손댈 필요가 없다.

## 6. 디자인 가이드

> 색상값·수치 등 구체적인 규칙은 **`DESIGN.md`가 기준 문서**입니다. 여기서는 방향만 요약합니다.

- **무드**: 미니멀 / 모던, **다크 기반**
- **컬러**: 웜 뉴트럴(따뜻한 기운이 도는 차콜/오프화이트) + 테라코타 포인트 1종
- **배경**: 화면 중앙으로 갈수록 어스름한 남색이 번지는 그라데이션 (인트로)
- **여백**: 넉넉한 여백으로 콘텐츠에 집중되는 레이아웃
- **타이포그래피**: 시스템 기본 산세리프 (별도 웹폰트 없음)
- **인터랙션**: 과하지 않은 수준. 크기 변화 대신 밝기·색·각도로 피드백을 준다

**다크로 정한 이유**: 인트로 화면은 요소가 적어서 밝은 배경에서는 여백이 "아직 안 채운 것"처럼 보였다. 어두운 배경에서는 같은 여백이 "의도된 깊이"로 읽히고, 커서 잔상이나 포인트 색도 훨씬 선명하게 살아난다.

## 8. 비기능 요구사항

- 별도 백엔드/DB 없이 정적 파일만으로 동작 (호스팅 용이성: GitHub Pages 등)
- 빠른 로딩 속도 (이미지 최적화 고려). 웹폰트를 쓰지 않고 시스템 폰트로 처리
- 프로젝트 추가 시 데이터 배열에 항목만 추가하면 되는 간단한 유지보수 구조

**외부 의존성 및 실패 대응**

GSAP은 CDN(jsDelivr)에서 버전을 고정해 불러온다. 외부 스크립트에 의존하므로, **불러오지 못해도 화면이 정상적으로 보여야 한다.**

| 실패 상황 | 대응 |
|---|---|
| GSAP 로드 실패 | CSS 애니메이션으로 자동 대체. 모든 콘텐츠는 그대로 보이고 링크도 정상 동작 |
| SplitText만 실패 | 인트로 타이틀이 글자 단위 대신 통째로 페이드업 |
| 썸네일 이미지 없음 | 대체 블록 표시 (5장 참고) |

**접근성**

- 포인터 인터랙션(자석 버튼·커서 잔상·3D 틸트)은 마우스가 있는 기기에서만 활성화. 터치 기기에서는 비활성
- `prefers-reduced-motion`을 켠 사용자에게는 모든 애니메이션을 끄고 정적 화면으로 제공
- 키보드 이동 시 포커스 표시(outline)를 포인트 색으로 제공
- 텍스트 대비는 웹 접근성 기준(4.5:1) 이상 유지 — 포인트 색 위 흰 글씨 금지 (`DESIGN.md` §2 참고)

## 9. 향후 고려사항 (Out of Scope, 현재는 제외)

- 태그/카테고리 필터링 기능 (태그는 표시만 하고 있음)
- 검색 기능
- 라이트모드 토글 (다크가 기본이 되었으므로, 필요해지면 반대 방향으로 검토)
- CMS/DB 연동을 통한 동적 데이터 관리
- 상세 페이지 또는 모달 뷰
- 프로젝트가 20건을 넘길 경우의 정렬/페이지네이션
