## 2. 사용자 시나리오

### 누가
공부에 동기부여가 필요한 사람. 시험·자격증·자기계발 등 목적은 구분하지 않는다. 1차 사용자는 개발자 본인.
PC 또는 노트북 **한 대**에서 브라우저로 사용한다.

### 언제
1. **공부를 시작할 때** — 브라우저에서 앱을 열고 과목을 고른 뒤 시작을 누른다
2. **공부하는 중** — 탭 제목에 표시된 경과 시간을 흘깃 보고 확인한다. 앱 화면으로 돌아오지 않는다
3. **주말에** — 주간 탭에서 한 주치를 점검한다

### 왜
어제보다 더 했다는 확인과, 덜 했다는 자각. 두 감정이 모두 다음 공부의 연료가 된다.
따라서 **오늘의 숫자는 항상 비교 기준과 함께 제시되어야 한다.** 절대값만으로는 어떤 감정도 발생하지 않는다.

### 설계 판단: 비교 기준
어제 하루만을 기준으로 삼으면 변동이 커서 이틀에 한 번은 마이너스가 뜬다. 부진이 며칠 이어지면 "볼 자신이 없어서" 앱 자체를 열지 않는 이탈이 발생한다.
→ **어제 대비와 최근 7일 평균 대비를 함께 표시한다.** 뿌듯함은 어제 대비에서, 안정적인 기준선은 7일 평균에서 얻는다.

## 4. 기술 스택

| 항목 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | React 19 + Vite | CSS Modules 무설정 지원 |
| 언어 | TypeScript | 열린 구간의 `endedAt` 부재를 컴파일 단계에서 방어 |
| 스타일 | CSS Modules | |
| 상태 관리 | React 내장 `useReducer` | 상태 전이가 곧 리듀서. 외부 라이브러리 불필요 |
| 차트 | 없음 | 막대 7개에 라이브러리는 과함. `div` 높이 % 처리 |
| 저장소 | `localStorage` | |

**Next.js 제외 사유**
서버가 없는 앱에 서버 프레임워크를 얹으면 `localStorage`가 서버 렌더링 시점에 존재하지 않아 hydration 불일치가 발생한다. 화면마다 `useEffect` 우회 코드가 붙고, 이 프로젝트에서 배울 것이 없는 문제에 시간을 쓰게 된다.

## 6. 상세 기능 명세

### 6.1 상태 전이

```
대기 ──시작──> 진행 중 ⇄ 일시정지
                  │           │
                종료        종료 / 30분 초과
                  ↓           ↓
              확정 저장 ──> 대기
                  ↑
        하트비트 끊김 → 복구 모달 → 확인
```

**모든 전이는 동일한 동작이다: 열린 구간을 닫고, 새 구간을 연다.**

| 전이 | 닫는 구간 | 여는 구간 |
|---|---|---|
| 시작 | — | study |
| 과목 교체 | study | study (새 과목) |
| 일시정지 | study | pause |
| 재개 | pause | study |
| 종료 | 현재 구간 | — |

```ts
function transition(nextKind: 'study' | 'pause' | null, subjectId: string | null) {
  const now = Date.now();
  closeOpenSegment(now);
  if (nextKind) openSegment(nextKind, subjectId, now);
  saveActive(now);
}
```

향후 기능이 추가되어도 이 함수의 호출 타이밍만 달라진다. 상태 코드는 늘지 않는다.

### 6.2 타이머
- 과목 선택 없이 시작 가능. 해당 구간은 `subjectId: null`로 저장되며 "미분류"로 집계
- 탭 제목 1초마다 갱신: `2:47:13 · 순공`
- **1분 미만으로 종료된 세션은 저장하지 않고 폐기**

### 6.3 일시정지
- 기본 30분 경과 시 자동 종료. 설정에서 최대 3시간까지 조정 가능
- pause 구간은 순공시간에 미포함 (총 체류시간에는 포함)
- **자동 종료는 백그라운드에서 돌지 않는다.** 앱 진입 시 임계값을 비교해 판정하며, 종료 시각은 일시정지를 누른 시점으로 소급한다

### 6.4 세션 복구
- 하트비트 30초 간격. `study:active`에만 기록하며 `study:segments`는 건드리지 않는다
- 진입 시 `lastHeartbeatAt` 경과 **2분 이내** → 모달 없이 그대로 진행
- **2분 초과** → 복구 모달 표시

복구 모달 선택지 (3개):
1. 마지막 활동 시각까지 저장 — `"마지막 활동이 23:47이었어요. 여기까지로 저장할까요?"`
2. 시간 직접 입력
3. 버리기

> 근거 없이 "언제까지 하셨나요?"라고 물으면 사용자는 기억하지 못하거나 후하게 적는다. 어제 대비 비교가 핵심인 앱에서 숫자가 부풀면 서비스 자체가 무의미해진다. 하트비트가 그 근거다.

- pause 상태로 끊긴 경우 → 모달 없이 조용히 확정 (어차피 순공시간에 미반영)

### 6.5 종료 결과 화면

종료 버튼을 누른 직후 전체 오버레이로 표시한다. 방금 공부를 끝냈고 아직 자리에 앉아 있는, 감정이 가장 크게 움직이는 시점이다.

```
        [결승선을 통과하는 캐릭터]

  이번 세션    2시간 20분
               앉은 시간 3시간 · 집중률 78%

  오늘 누적    4시간 05분
  어제         3시간 12분      +53분
```

- **주인공은 이번 세션 시간.** 오늘 누적과 어제는 아래에 작게 붙는다
- 집중률 = 순공시간 ÷ 총 체류시간. 일시정지가 없었다면 표시하지 않는다
- 어제 값은 하루 최종 기록을 그대로 사용한다. 시각 정렬 계산 없음
- **종료할 때마다 매번 표시**
- 닫으면 타이머 탭으로 복귀

**어제 대비 표기 규칙**

| 상황 | 표기 |
|---|---|
| 오늘 누적 < 어제 최종 | `어제 기록까지 3시간 남음` |
| 오늘 누적 ≥ 어제 최종 | `+53분` |

하루 중간에 종료하면 오늘 누적이 어제 최종보다 적은 것이 정상이다. 이를 `-3시간`으로 표시하면 아직 하루가 끝나지 않았는데도 패배로 읽히고, 매번 표시하는 구조에서는 이 오해가 하루에 두세 번 반복된다. 남은 시간으로 적으면 같은 정보가 다음 세션의 목표로 바뀐다.

- 진행 바의 달리는 캐릭터를 재사용해 결승선 통과 연출을 넣는다 (= 목표 달성 축하 효과)

### 6.6 미분류 시간
- 과목별 분포에 "미분류" 항목으로 표시
- 주간 → 날짜 클릭 → 타임라인에서 구간을 눌러 과목 지정
- **과목 변경만 허용한다.** 시작·종료 시각 편집은 구간 겹침·하루 경계 넘김 검증이 필요해 범위가 급격히 커진다

### 6.7 목표
- **하루 목표 하나만** 설정한다
- 주간 목표를 따로 두면 하루 목표와 어긋날 때 어느 쪽이 기준인지 모호해진다 (주 5일인가 7일인가). 주간 화면에서는 하루 목표를 막대 위 가로선으로 그어, 7개 중 몇 개가 선을 넘었는지로 표현한다
- 과목별 목표는 미분류 시간 때문에 달성률이 부정확해지므로 제외

### 6.8 하루 경계
- 기본 **05:00**. 설정에서 변경 가능
- 하루 = 그날 05:00 ~ 다음 날 05:00. 밤 11시~새벽 1시 공부는 전날 기록으로 산입
- 각 구간에 `studyDate`를 계산해 저장하고, 오늘 시간·주간 집계·과목 분포를 전부 이 필드로 처리한다

**경계를 넘는 세션 — 자르지 않는다**

세션은 **시작한 시점의 `studyDate`에 통째로 귀속된다.** 23:00에 시작해 08:00에 끝낸 9시간은 전부 시작한 날의 기록이다.

05:00에서 잘라 6시간/3시간으로 나누면 어느 쪽도 실제 공부량으로 읽히지 않는다. 밤샘은 사용자에게 한 덩어리의 공부이고, 그것을 두 개의 어중간한 기록으로 만들면 어제 대비 비교가 양쪽 모두에서 어긋난다.

- **세션 내 모든 구간이 세션 기준일을 물려받는다.** 구간 각자의 시작 시각으로 계산하지 않는다. 그러지 않으면 05:30의 과목 교체 하나로 세션이 두 날로 갈라져, 자르지 않기로 한 결정이 무의미해진다
- 기준일은 `study:active`에 보관하고, 세션 중 열리는 모든 구간에 찍는다

**대신 실제 시각 범위를 표기한다**

자르지 않는 대신, 기록이 언제까지 이어졌는지를 숨기지 않는다.

| 상황 | 표기 |
|---|---|
| 같은 날 | `8월 12일 14:00 ~ 16:20` |
| 경계 넘김 | `8월 12일 23:00 ~ 8월 13일 08:00` |

종료 결과 화면과 하루 상세 타임라인에서 사용한다. 경계를 넘은 구간만 양쪽 날짜를 모두 적어, 평소 표기가 길어지지 않게 한다.

**진행 중 세션의 "오늘"**

새벽 6시에 세션이 돌고 있으면 달력상 오늘은 새 날짜지만 그 세션은 전날에 쌓이는 중이다. 이때 대시보드가 새 날짜(0분)를 보여주면 타이머는 도는데 숫자가 0인 상태가 된다.
→ **세션이 진행 중인 동안 대시보드의 "오늘"은 세션 기준일을 따른다.** 종료하면 실제 오늘로 돌아온다.

### 6.9 다중 탭
- 다른 탭에서 실행 중이면 시작 버튼 비활성화 + 안내 표시
- `BroadcastChannel` 또는 `study:active`의 `lastHeartbeatAt` 검사로 판정

### 6.10 데이터 구조

```
study:settings   { dayBoundaryHour: 5, pauseTimeoutMin: 30, theme, version: 1 }
study:subjects   [ { id, name, color, order, archived } ]
study:goal       [ { targetMinutes, effectiveFrom } ]
study:segments   [ { id, sessionId, subjectId | null, kind, startedAt, endedAt, studyDate } ]
study:active     { sessionId, studyDate, status, currentSubjectId, openSegment, lastHeartbeatAt }
```

- `id`는 UUID. 향후 서버를 붙일 경우 그대로 이관 가능
- `active.studyDate`는 **세션 기준일**. 세션 중 열리는 모든 구간이 이 값을 물려받는다 (§6.8)
- `goal`은 단일 값이 아니라 **`effectiveFrom`을 가진 이력 배열**이다. 목표를 바꿨을 때 지난주 달성률이 소급 변경되면 안 되기 때문이며, 그러려면 이전 목표 값이 남아 있어야 한다. 특정 날짜의 목표는 `effectiveFrom <= 그날` 중 가장 늦은 항목으로 정한다
- 순공시간 = `kind === 'study'` 구간의 합 / 총 체류시간 = 전체 구간의 합

### 6.11 백업
- 설정에서 JSON 전체 내보내기 / 가져오기
- 가져오기 시 덮어쓰기 확인 다이얼로그
- 마지막 백업 후 7일 경과 시 설정 탭에 안내 배지

**비활성/플레이스홀더 색상 출처**
DESIGN.md의 Dust Taupe(`#D1CDC7`, "whisper" 텍스트용)를 그대로 차용했다. 기존 팔레트는 본문·보조 텍스트 두 단계뿐이라 미분류 표시, 기록 없는 요일 막대, 보관된 과목처럼 "존재하지만 강조하지 않는" 상태를 표현할 색이 없었다. 보조 텍스트보다 한 단계 더 낮춰 이 상태들에 쓴다. 다크 모드 값(`#6A6156`)은 테두리(`#3A332A`)와 보조 텍스트(`#9A9082`) 사이를 보간해 새로 만들었다.

**과목 색상** — 아래 8색을 순서대로 자동 배정, 설정에서 변경 가능.
(종이 배경 위에서 튀지 않도록 채도를 낮춰 통일)

**색상 선정 근거**
- 다크 값은 라이트 값과 동일한 색상(hue)을 유지한 채 명도만 약 9~12%p 올렸다. 강조·달성 색이 다크 모드에서 밝아지는 것과 같은 패턴이라 팔레트 전체의 일관성이 유지된다
- **올리브**는 원래 계산상 달성 색(`#7A8B4F`)과 색상값이 거의 겹쳤다. 목표 달성 표시와 특정 과목 태그가 같은 색으로 보이면 "이 과목을 공부해서 달성했나?"처럼 읽는 순간 혼동이 생기므로, 올리브를 더 밝고 채도 낮게 밀어 구분했다
- **테라코타**는 강조(진행 바) 색과 색상 계열이 겹치지만, 진행 바는 화면 전체 폭의 굵은 바이고 과목 태그는 작은 배지·점이라 형태 차이로 이미 구분되어 그대로 두었다

### 타이머 화면
- 상단에 시간 숫자, 그 아래 목표 대비 가로 진행 바
- **진행 바 위 현재 지점에 간소화된 동물 캐릭터가 달린다**

캐릭터가 담당하는 역할:

| 상황 | 표현 |
|---|---|
| 진행 중 | 달린다 |
| 일시정지 | 멈춰 선다 — 타이머 상태를 텍스트 없이 알림 |
| 목표 달성 | 결승선 통과 연출 (= 축하 효과) |
| 초과 달성 | 결승선 너머에 서 있고 바 위에 `142%` 표시 |

구현 주의사항:
- 이미지 파일이 아닌 **인라인 SVG**. 다크 모드 색상 대응 때문
- 위치는 `transform: translateX(%)` + `transition`. 1초 갱신을 그대로 반영하면 뚝뚝 끊긴다
- 다리 움직임은 2프레임 교대로 충분
- `prefers-reduced-motion` 시 달리기 애니메이션만 끄고 위치 이동은 유지

### 타이포·간격
- 한글 본문 Pretendard
- **타이머 숫자에 `font-variant-numeric: tabular-nums` 필수.** 매초 바뀌는 숫자의 폭이 다르면 레이아웃이 미세하게 흔들려 눈에 거슬린다
- 크기: 타이머 64px / 제목 20px / 본문 15px / 보조 13px
- 간격은 8의 배수. 모서리는 카드 12px, 버튼 8px
